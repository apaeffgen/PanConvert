# PanConvert - Debug Notes & Learned Issues

## 2026-07-25: Qt6Core.dll Stack-Buffer-Overflow Crash (0xc0000409)

### Problem
- **Symptom:** `python.exe` crasht mit Exception `0xc0000409` in `Qt6Core.dll`
- **Plattform:** Nur Windows (nicht Linux/Mac)
- **Modul:** `Qt6Core.dll` (Version 6.11.1.0 und 6.8.2.0 getestet)
- **Faulting Offset:** `0x00000000000267a8` (variabel)
- **Prozess:** `.venv3.11\Lib\site-packages\PyQt6\Qt6\bin\Qt6Core.dll`

### Analyse
- `0xc0000409` = `STATUS_STACK_BUFFER_OVERRUN` (Stack-Smash-Detektor)
- Windows `/GS`-Mechanismus erkennt Stack-Corruption zuverlässig
- Linux/Mac erkennen es oft nicht (oder zu spät)
- **Wichtig:** Crash trat BEIDE Qt-Versionen auf (6.11.1 UND 6.8.2) → Kein reiner Qt-Bug
- Ursache: Code-Problem das Qt-Interna korruptiert (vermutlich QSettings-Typ-Konfusion)

## 2026-07-25: Tiefe Code-Analyse - Crash bleibt bestehen

### Durchgeführte Fixes
1. **`settings.status()` entfernt** — Qt6 API entfernt, verursacht Stack-Corruption!
   - 15 Aufrufe in 9 Dateien entfernt
   - **NICHT die Ursache** des Crashes (Crash bleibt)
2. **`str.rstrip()` Missbrauch gefixt** — War keine statische Funktion
3. **`convert_binary` Bug:** Sendet Error-Nachricht als stdin an Pandoc
4. **QSize/QPoint QVariant-Konversion:** `settings.value("size")` gibt QVariant zurück

### 🔴 Neue tiefe Probleme gefunden

#### A. Module-Level QSettings Instanzen (CRITICAL)
**Problem:** QSettings wird auf Module-Ebene instantiiert, BEVOR QApplication existiert.

**Betroffene Dateien:**
| Datei | Zeile | Code |
|-------|-------|------|
| `converter/batch_converter.py` | 25, 27 | `settings = QSettings(...)` |
| `converter/lyx_converter.py` | 27 | `settings = QSettings(...)` |
| `converter/manual_converter.py` | 24 | `settings = QSettings(...)` |
| `helpers/interface_pandoc.py` | 30 | `settings = QSettings(...)` |
| `language/messages.py` | 25 | `settings = QSettings(...)` |

**Warum das crasht:** QSettings initialisiert Registry-Zugriff auf Module-Import. Wenn PyQt6-Interna noch nicht vollständig geladen sind, korruptiert dies den Stack.

#### B. `strtobool()` — Plattform-spezifische Behandlung UMDREHT
```python
# dialog_preferences.py:230-231
if platform.system() == 'Darwin':
    self.ui.ButtonFromMarkdown.setChecked(From_Markdown)  # macOS: direct bool
else:
    self.ui.ButtonFromMarkdown.setChecked(strtobool(From_Markdown))  # Windows: needs strtobool
```

**Problem:** Die Logik ist für Windows/Mac vertauscht!
- Windows gibt `QVariant` zurück (nicht bool)
- Mac gibt `bool` zurück
- Die Bedingung `== 'Darwin'` ist für macOS, aber Windows braucht strtobool!

#### C. `convert_binary` sendet Error-Nachricht als stdin
```python
# manual_converter.py Zeile ~80:
output = error_unknown()  # Gibt ERROR-MESSAGE zurück!
output1, error1 = p.communicate(output.encode('utf-8'))  # Sendet Error als stdin!
```

#### D. PyQt6-WebEngine QtWebEngineView in Dialogen
```python
# panconvert_diag_fromformat.py, toformat.py, help.py, info.py:
self.textBrowser = QtWebEngineWidgets.QWebEngineView(...)
```
QtWebEngine hat eigene Chromium-Init-Prozesse die mit QSettings kollidieren können.

#### E. Global Variable Kollision
```python
# main_gui.py:
global openfile, filelist, actualLanguage, number, uri

# converter/batch_converter.py:
global openfiles, filelist

# converter/lyx_converter.py:
global path_pandoc

# dialogs/dialog_batch.py:
global openfiles, batch_open_path

# dialogs/dialog_openuri.py:
global uri
```
Mehrere Module definieren dieselben globals → undefiniertes Verhalten.

### 🔍 Verbleibende Verdächtige (nach QSettings-Fix)

1. ~~**QSettings auf Module-Ebene** — Initialisiert vor QApplication~~ ❌ AUSGESCHLOSSEN
2. **PyQt6-WebEngine Init** — Chromium-Process mit QSettings-Konflikt
3. **SIP 13.11.1 + Qt6.11.1 Binding** — Möglicher ABI-Call Bug 🔴 HAUPTVERDÄCHTIG
4. **Windows Registry Access** — QSettings schreibt auf Registry, korruptiert Stack
5. **Thread-Safety** — QSettings nicht thread-safe, aber Code nutzt keine Threads

**Erkenntnis:** Der Crash blieb trotz aller Code-Reinigung bestehen → **Kein Code-Bug**

### 📋 Phase 4: Runtime-Crash bei Konvertierung

**Neues Symptom:** Nach PyQt6-Downgrade startet App, aber crasht bei **markdown → HTML Konvertierung**

**Debugging-Schritte:**
1. Minimal-Testscript erstellt → ✅ Läuft durch
2. Vollständigen User-Flow simuliert → ❌ Crash bei `check_format()`
3. Trace-Logging eingefügt → 📍 Crash in `get_pandoc_formats()`

**Erster Fehler:** `NameError: name 'path_pandoc' is not defined`
- **Ursache:** `path_pandoc` wurde bei QSettings-Cleanup entfernt
- **Fix:** Als leeres Modul-Variable wieder hinzugefügt

**Zweiter Fehler:** `ValueError: 'Options:' is not in list`
- **Ursache:** Pandoc 3.10.1 hat neues Help-Format, `get_pandoc_version()` extrahiert fälschlich 0
- **Details:**
  - Pandoc 3.10.1 → `versionstr = "pandoc 3.10.1"`
  - Alter Code: `version_tmp[10:15]` → `"3.10"` → `int("310")` = 310 (falsch)
  - Oder: `version_tmp[7:10]` (Linux-Pfad) → `"10.1"` → `int("101")` = 101
  - `version < 118` → True → versucht `help_text.index('Options:')` → ❌
- **Fix:** Regex `r'pandoc\s+(\d+)'` extrahiert Major-Version (3)
- `get_pandoc_formats()`: `version < 118` → `version < 2`

**Ergebnis:** Markdown → HTML Konvertierung funktioniert ✅

### 📋 Phase 5: Final Verification

**Test-Szenario:**
```python
Input:  # Hello World\n\nThis is a **test** of PanConvert.
Output: <h1 id="hello-world">Hello World</h1>\n<p>This is a <strong>test</strong> of PanConvert.</p>
```

**Ergebnis:** ✅ Konvertierung korrekt

### 💡 Lessons Learned

1. **Stack-Buffer-Overflow (`0xc0000409`) ist ein Framework-Bug, kein Code-Bug**
   - Windows `/GS`-Mechanismus ist extrem zuverlässig
   - Wenn es auf Windows crasht, aber nicht auf Linux/Mac → Qt/PyQt-Problem

2. **Code-Cleanup ohne Reproduktion ist wertlos**
   - Module QSettings zu entfernen war gut, aber nicht die Lösung
   - Immer zuerst isolieren, dann fixen

3. **Pandoc Version Detection muss robust sein**
   - `pandoc -v` Ausgabe variiert zwischen Versionen
   - Immer regex-basiert parsen, nicht string-slicing
   - Major-Version vs. Build-Version unterscheiden

4. **Module-Variable als Fallback**
   - `path_pandoc` als globale Variable war eine pragmatische Lösung
   - Besser: Dependency Injection oder Settings-Manager

## 2026-07-25: Fix Attempt — Module-Level QSettings Eliminiert

### 🔧 Durchgeführte Änderungen

**Pattern angewendet:**
```python
# BEFORE (crashes at import time):
settings = QSettings('Pandoc', 'PanConvert')
path_pandoc = settings.value('path_pandoc')

# AFTER (lazy, safe):
def _get_settings():
    """Lazy QSettings getter - avoids module-level instantiation."""
    return QSettings('Pandoc', 'PanConvert')

# In functions:
settings = _get_settings()
path_pandoc = settings.value('path_pandoc', '')
```

**Files changed:**
| File | Module-Level QSettings Removed |
|------|------|
| `source/converter/batch_converter.py` | `settings`, `batch_settings`, `path_pandoc` (line 25-27) |
